## 1. 现状审计

### 1.1 真实截图里暴露的问题

| 位置 | 问题 | 影响 |
|---|---|---|
| 项目列表 | 顶部常驻「新建项目」表单，项目以表格罗列 | 首页没有重点，项目多了不可用 |
| 项目总览 | 四个数字 + 两张表 | 看完不知道下一步该干什么 |
| 用例页 | 1333 条用例，一次渲染；只有覆盖树 / 全部用例两个视角 | 审核是核心工作，却没有审核工作台 |
| 执行详情 | `stats` 直接 `JSON.stringify`，把 20 行 pytest stdout 塞进首屏 | 最关键的信息（哪条失败、为什么）被淹没 |
| 缺陷页 | 宽表格 + 每行两个按钮，没有详情 | 无法判断真假，无法看证据和复现 |
| 知识源 | 操作按钮被挤成竖排，行高巨大，版本是 40 位 hash | 页面粗糙，信息密度失控 |
| 全局 | 枚举全是英文（completed / pending / pass / functional） | 认知成本高，不像成品 |
| 全局 | 触发任务后只提示「刷新」 | 不知道任务在跑、跑到哪、有没有失败 |
| 全局 | 没有搜索、筛选、分页、排序、实时刷新、空状态引导 | 只能靠肉眼和刷新 |
| 全局 | 没有导航壳，项目内切页靠一排 tab | 深层页面容易迷路 |

### 1.2 功能性缺口（已核对代码）

1. **任务不可见**：后端有 `tasks` 表和 `/projects/{id}/tasks`，前端完全没用。
2. **运行不实时**：执行中页面不会自动更新，状态机五步（排队/准备/执行/分析/完成）没有展示。
3. **用例不能改**：后端 `PATCH /cases/{id}` 支持修改，前端只有启用/停用。
4. **不能只跑选中的用例**：后端 `POST /runs` 已支持 `case_ids`，前端没有入口。
5. **不能重跑失败**：没有「重跑失败用例」入口。
6. **归因不能人工修正**：后端 `POST /results/{id}/attribution` 没有 UI。
7. **截图/产物无法访问**：后端没有 artifacts 静态路由，`screenshot_path` 是死字段。
8. **用例列表无分页**：前端固定 `limit=5000`，1277 条项目会卡。
9. **项目不能编辑/删除**：列表页只有创建。
10. **没有项目健康检查**：base_url 是否可达、LLM 是否可用、worker 是否在跑，全靠猜。
11. **执行 `stats` 污染**：`sandbox.stdout/stderr` 被写进统计，前端直接展示。
12. **一致性没有详情**：只有一行文字，看不到三方证据对比。

## 2. 产品原则

1. **工作流优先，数据其次**：每个页面回答「现在发生什么、我该做什么」，而不是「数据库里有什么」。
2. **一屏一个主动作**：总览的主按钮永远是当前最该做的事（审核 / 执行 / 处理缺陷）。
3. **证据随手可见**：断言依据、代码位置、请求响应，点一下就到，不要求用户翻 JSON。
4. **状态说人话**：所有枚举中文标签 + 统一颜色；技术标识（ID、hash、路径）降级为次要信息。
5. **实时感**：后台任务有全局指示器、页面自动轮询、完成有 toast。
6. **密度可控**：列表优先用双行行式布局 + 筛选 + 分页，不再一张大表塞所有字段。
7. **个人自用也要像产品**：不引入登录/多租户，但交互完成度按产品标准做。

## 4. 视觉系统

### 4.1 方向

**深海军蓝侧栏 + 浅色工作区**。像 Linear / Vercel 的完成度，但保留航海气质：
侧栏是「船舱」，内容是「甲板」；主色用海绿色，失败用珊瑚红，不稳定用琥珀色。

- 背景 `#F5F6F8`，卡片纯白，1px `#E4E7EC` 边框，12px 圆角，极轻阴影。
- 侧栏 `#0B1220`，选中项 `rgba(255,255,255,.08)` + 左侧 2px 海绿条。
- 主色 `#0E9384`（hover `#0B7D70`，soft `#CCFBF1`）。
- 语义色：通过 `#067647` / 失败 `#B42318` / 不稳定 `#B54708` / 运行中 `#175CD3` / 中性 `#667085`。
- 字体：系统 UI 栈（优先 Inter / PingFang SC）；代码与 ID 用 JetBrains Mono / SFMono。
- 字号：12 / 13 / 14（正文）/ 16 / 20 / 28（指标数字）。行高 1.5。
- 间距 4 的倍数；卡片内边距 20；表格行高 48。
- 动效 150ms ease；只用于 hover、抽屉、toast，不做花哨动画。

### 4.2 组件清单

`Button`（primary/secondary/ghost/danger，3 尺寸）、`StatusPill`（圆点+中文）、`Card`、
`Metric`（数字+标签+趋势）、`Sparkline` / `Donut` / `Bars`（纯 SVG，不引图表库）、
`DataList`（行式列表，非大表格）、`Tabs`、`FilterBar`、`Drawer`、`Modal`、`Toast`、
`Skeleton`、`EmptyState`、`CopyButton`、`Field`、`Segmented`、`CommandPalette`、`Timeline`。

### 4.3 文案与状态映射（统一收口）

| 域 | 原值 → 中文 |
|---|---|
| run | queued 排队中 · preparing 准备环境 · running 执行中 · analyzing 分析中 · completed 已完成 · failed 失败 · cancelled 已取消 |
| case | pending 待审核 · enabled 已启用 · disabled 已停用 · needs_review 待复核 |
| result | pass 通过 · fail 失败 · flaky 不稳定 · error 错误 · skipped 跳过 |
| finding | pending 待确认 · confirmed 已确认 · false_positive 误报 |
| dimension | functional 功能 · boundary 边界 · security 安全 · performance 性能 |
| source | code 代码 · openapi OpenAPI · doc 文档 |
| task | queued 排队中 · running 运行中 · succeeded 成功 · failed 失败 · cancelled 已取消 |
| severity | critical 严重 · high 高 · medium 中 · low 低 |

## 5. 页面规格

### 5.1 项目组合页 `/`

**目的**：一屏看清所有项目健康度，快速进入或新建。

- 顶栏：标题「项目」+ 搜索 + 「新建项目」主按钮（打开向导，不再常驻表单）。
- 项目卡（3 列自适应）：
  - 名称、描述、base_url（mono，截断）；
  - 最近执行：状态 pill、通过率、相对时间、7 次执行 sparkline；
  - 覆盖：功能覆盖率进度条；待审核用例数；待确认缺陷数；
  - 左下角「需要注意」红点（有待审核 / 有失败 / 目标不可达）；
  - 右上角 `⋯`：编辑、删除、复制配置。
- 空状态：插画式图标 + 「连接第一个被测项目」+ 三步说明。
- 新建向导（3 步）：
  1. 基本信息（名称、描述、base_url）；
  2. 连接知识（仓库目录 / 文档 URL / OpenAPI，可跳过）；
  3. 连通性检查（探测 base_url、LLM、worker）+「创建并开始扫描」。

### 5.2 项目总览 `/projects/:id`

**目的**：回答「现在怎么样、下一步做什么」。

- 顶部：项目名 + 环境 pill（可达/不可达）+ 最近执行时间 + 主按钮「执行」。
- **行动中心**（最显眼）：按优先级列出待办卡片：
  - 有 N 条用例待审核 →「去审核」；
  - 最近执行有 N 条失败 →「查看失败」；
  - 有 N 条待确认缺陷 →「去分诊」；
  - 有 N 个接口三方不一致 →「查看差异」；
  - 超过 7 天没执行 →「重新执行」。
- 指标行：功能覆盖率、用例通过率、已确认缺陷、待审核。
- 趋势区：最近 10 次执行通过率折线 + 堆叠结果条（SVG），hover 显示明细。
- 覆盖区：模块覆盖率条形列表（点击跳用例工作台并带筛选）。
- 最近执行：5 条紧凑列表，点进详情。

### 5.3 测试设计 `/projects/:id/cases`（核心页）

**目的**：把「审用例」变成 10 分钟内能完成的工作，而不是滚 1300 行表格。

三栏工作台：

```
┌ 覆盖树 260px ┬ 用例列表 380px ─────────┬ 详情（自适应，≥520px）────────┐
│ 模块         │ 搜索 / 维度 / 状态筛选    │ 标题 + 维度 + 优先级 + 状态     │
│  功能点 12   │ ☐ 全选  批量启用/停用/执行│ 步骤时间线（请求/操作）         │
│   ✓ 已覆盖   │ ─────────────────────    │ 断言表：期望 / 实际依据 / 状态  │
│   ! 缺正常流 │ ▸ 用例标题               │ 依据卡片（可展开原文）           │
│              │   维度 · 功能点 · 依据数  │ 缺少输入提示                    │
│              │ ▸ ...                    │ 底部固定操作栏：启用/停用/编辑/执行│
└──────────────┴──────────────────────────┴──────────────────────────────┘
```

- 列表默认只显示「待审核」，顶部 segmented：待审核 / 已启用 / 全部。
- 服务端分页（每页 50）+ 排序（优先级、更新时间）。
- 多选后：批量启用、批量停用、**执行选中用例**。
- 详情内可直接编辑标题、步骤、断言、依据（PATCH），保存写 human_feedback。
- 键盘：`J/K` 上下、`A` 启用、`X` 停用、`E` 编辑、`/` 聚焦搜索、`Esc` 关闭。
- 覆盖树点击功能点 = 过滤列表；无正常流功能点红色标记。
- 顶部工具栏：「抽取功能点」「生成用例」转为带进度的异步按钮，完成后 toast + 自动刷新。

### 5.4 执行列表 `/projects/:id/runs`

- 顶部：主按钮「执行全部已启用」+ 下拉（只跑功能/安全/边界/性能）。
- 行式列表：状态 pill、通过率环、总数/通过/失败/不稳定、耗时、触发方式、时间、操作（查看 / 取消 / 导出）。
- 执行中行内显示进度（已有结果数 / 总数，若后端能提供）+ 脉冲动画。
- 自动轮询 2s；完成的执行弹出 toast。

### 5.5 执行详情 `/projects/:id/runs/:runId`

- 头部：状态、起止时间、耗时、环境（base_url、沙箱）、操作（取消、重跑失败、导出 HTML）。
- **状态机时间线**：准备环境 → 执行 → 失败重跑 → 归因 → 完成，每步时间与结果。
- 结果分布：Donut（通过/失败/不稳定/错误/跳过）+ 通过率。
- 失败优先：默认 tab「失败」，其次全部/通过/不稳定/错误。
- 结果行：用例、维度、状态、耗时、归因摘要；点击打开右侧抽屉：
  - 请求（method/url/headers/body，格式化 + 复制 curl）；
  - 响应（状态码/headers/body，JSON pretty）；
  - 断言对比（期望 vs 实际，失败项高亮）；
  - 日志（等宽、可复制）；
  - 归因（类别、理由、置信度）+「修正归因」；
  - 截图/trace（有则展示，后端提供 artifacts 路由）。
- 底部：重跑失败用例（调用 create_run with case_ids）、导出。

### 5.6 缺陷 `/projects/:id/findings`

- 顶部：来源 segmented（全部/黑盒/白盒）、状态 tab（待确认/已确认/误报）、严重级别筛选、搜索。
- 行式列表：严重度色条、标题、来源、模块、关联用例、时间、状态。
- 右侧抽屉：
  - 描述 + 风险类型；
  - 证据（断言/文档引用/代码位置，代码位置可复制 `文件:行号`）；
  - 复现命令（一键复制）；
  - 关联执行结果（跳转）；
  - 操作：确认 / 误报 / 重新打开。
- 批量确认/误报；白盒走查触发后展示任务进度。

### 5.7 理解 `/projects/:id/knowledge`

三个 tab：

1. **知识源**：卡片行（类型图标、名称、位置、角色、状态、版本短 hash、块数/接口数、解析时间）+ 操作（重新解析/删除）。顶部「自动导入」与「添加知识源」打开抽屉；解析中显示进度并可轮询。
2. **接口清单**：搜索 + 方法筛选 + 一致性筛选；行式列表（方法徽章、路径 mono、说明、来源、一致性 pill）；点击抽屉看参数/请求体/响应 schema/示例/来源证据。
3. **一致性**：强信号/弱信号分段；每条差异卡片显示接口、类型、三方证据对照、修复建议；支持导出 Markdown、一键生成 finding。
4. **Spec 变更**：若存在快照，展示版本 diff（新增/删除/变更接口），受影响的用例标 needs_review。

### 5.8 Agent 活动 `/projects/:id/activity`

- 任务中心：排队/运行/成功/失败的 task 列表，kind 中文、耗时、结果摘要、错误；运行中自动刷新。
- 轨迹：时间线（规划 → 工具调用 → 输出），可展开输入输出、token、耗时；过滤 kind。
- 用量：今日/近 7 天 token 与调用数（若能取到）。

### 5.9 设置

- **全局设置**：分组卡片（模型 / Embedding / 沙箱 / Worker / 安全），每项含说明与「当前值 / 已覆盖」；顶部「测试连通性」输出可读结果（LLM ✓ 延迟、沙箱 ✓、数据库 ✓）。
- **项目设置**：被测地址、测试账号（密码打码 + 替换）、隔离模式、被测库 DSN、危险区（删除项目，需输入名称确认）。

- 统一 `labels.ts`、`format.ts`、`usePolling`、`Toast`。
- 路由重组：`knowledge`、`activity`；旧路径重定向。
- 验收：任意页面有统一壳、无英文枚举、任务运行有全局提示。

### 阶段 B：核心工作流

- 项目组合页 + 新建向导 + 项目总览（含行动中心）。
- 用例三栏工作台 + 编辑 + 批量 + 跑选中。
- 执行列表 + 执行详情（时间线、抽屉、重跑失败、导出）。
- 验收：从「新项目」到「审核 20 条 → 执行 → 看失败 → 修归因 → 重跑」不用刷新页面。

### 阶段 C：知识与缺陷

- 知识源 / 接口 / 一致性 / spec diff。
- 缺陷分诊抽屉 + 批量操作 + 产物展示。
- 验收：任一缺陷能在一个抽屉内看完证据、复现命令、关联执行。

### 阶段 D：打磨

- 命令面板、执行趋势、响应式、暗色、空状态、错误态、快捷键。
- 验收：`npm run typecheck && npm run build` 通过；核心流程有 Playwright 冒烟（可选）。

---

## 8. 明确不做

- 不重写后端编排/执行引擎（已能跑通，只补 API 缺口）。
- 不引入重型 UI 框架/图表库（保持零新增运行时依赖，SVG 手绘）。
- 不做完整登录 / SSO / 计费；仅保留轻量项目角色与 tenant 校验（见 `docs/automation-roadmap.md`）。
- 不为了「好看」删掉可追溯信息，只做分层与折叠。
- 不追求用例数量，不为覆盖率造无用例。

## 9. 风险与取舍

| 风险 | 应对 |
|---|---|
| 重做期间旧页面不可用 | 保留路由与 API，新页面按阶段替换，随时可回退 |
| 后端分页接口变更影响脚本 | 新增 `/cases/page`，旧 `/cases` 保持兼容 |
| 轮询压力 | 仅活动任务/执行中页面轮询，2–3s，页面隐藏时暂停 |
| 数据里已有英文/脏字段 | 前端做展示层映射与截断，不在迁移里清洗 |
| 深色侧栏与浅色内容割裂 | 统一边框/阴影/圆角，侧栏只做导航，不承载正文 |
